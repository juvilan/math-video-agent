# 토큰 예산 — 언제 이미지를 보고 언제 텍스트로 때우나

이 파이프라인에서 **압도적으로 비싼 동작은 렌더된 이미지를 Read
하는 것**이다. 1080p PNG 한 장이 이 문서 전체보다 비싸다.
그런데 이미지를 안 보면 조용한 실패를 놓친다.

해법은 "이미지를 덜 보자"가 아니라 **이미지로만 알 수 있는 것과
좌표로 알 수 있는 것을 갈라내는 것**이다.

---

## 비용 순서

```
싼 것 ────────────────────────────────────────────→ 비싼 것

 콘티 고치기   layout 검사   대조표 1장   스틸 1장   씬 재렌더 후
 (텍스트)      (텍스트)      (16프레임)   (1프레임)  다시 전부 확인
```

**왼쪽에서 잡을 수 있는 문제를 오른쪽에서 잡지 않는다.**

---

## 1. 콘티에서 잡는다 (제일 쌈)

기획 단계에서 확정하면 애초에 안 생기는 문제들:

| 콘티에서 정하는 것 | 안 정하면 생기는 일 |
|---|---|
| 화면 영역 분할 (수식 위 / 그림 가운데 / 자막 아래) | 라벨이 그림 위에 겹침 → 스틸 보고 발견 → 재렌더 |
| 변수별 색 | 씬마다 색이 달라짐 → 대조표 보고 발견 → 여러 씬 재렌더 |
| 비트별 목표 길이 | 타이밍이 안 맞음 → 프리뷰 보고 발견 → run_time 전부 조정 |
| 비트 순서 | 순서를 바꾸면 씬 코드 전체를 버림 |

비트 순서를 3단계(뼈대)에서 바꾸면 **버리는 코드가 0줄**이다.
코딩 후에 바꾸면 씬 코드 + 렌더 + 확인한 이미지가 전부 날아간다.
`math-storyboard` 가 단계마다 멈추는 이유가 이것이다.

콘티에 **화면 배치표**를 반드시 넣는다:

```
상단 y=+2.6~+3.4   제목 / 수식
중앙 y=-1.5~+2.2   그림 (여기만 씬마다 바뀐다)
하단 y=-3.4~-2.6   자막
좌우 |x| ≤ 6.4     title-safe. 이 밖은 잘린다
```

## 2. `mv.py layout` — 이미지 없이 좌표로 (거의 공짜)

```bash
python3 mv.py layout scenes/circle.py Unroll
```

씬을 끝까지 돌리되 **이미지를 만들지 않고** 매 `play` 마다 화면
배치를 좌표로 검사해 텍스트로 보고한다.

```
배치 문제 1종:

  [play#19~play#21] MathTex('r') title-safe 밖
                    (x 6.28~6.47, y -0.05~0.15, 안전 ±6.40/±3.60)
```

**잡는 것**
- 화면 밖으로 나간 객체
- title-safe 밖으로 나간 글자
- 글자끼리 겹침
- 효과음 파일 없음

**못 잡는 것**
- 색 대비 (배경과 붙는지)
- 그림이 의미가 통하는지
- 움직임이 자연스러운지
- 변형 중간이 뭉개지는지

`scene_base.MathScene` 을 상속한 씬에서만 동작한다.
직접 돌리려면 `MV_LAYOUT=1` 환경변수를 켠다.

**씬을 쓴 직후 여기부터 돌린다.** 여기서 나온 걸 다 고친 다음에
이미지를 본다. 순서를 바꾸면 같은 이미지를 두 번 본다.

---

## 3. 스틸 1장 — 구도 최종 확인

`layout` 이 통과한 뒤 **씬당 한 장**만 본다.

```bash
python3 mv.py still scenes/circle.py Unroll
```

여기서 볼 것은 좌표로 알 수 없는 것뿐이다: 색이 배경과 붙는지,
그림이 의도한 모양인지, 한글이 네모로 나오는지.

- 구간이 궁금하면 `-n 3,5` 로 그 구간만
- **같은 씬의 스틸을 세 번 이상 보고 있으면** 코드로 고칠 수 있는
  걸 눈으로 찾고 있는 것이다. `layout` 으로 돌아간다

---

## 4. 대조표 1장 = 프레임 16장

```bash
python3 qc.py sheet out.mp4 -g 4x4
```

64초 영상 전체가 한 장이다. **프레임 16장을 따로 Read 하는 것의
1/16 비용**이다. 검수(⑥)에서 이걸 먼저 보고, 이상한 칸이 있을 때만
`strip` 이나 `guides` 로 확대한다.

`stats` 는 순수 텍스트라 사실상 공짜다. 항상 먼저 돌린다.

---

## 5. 재렌더는 마지막 수단

씬 하나를 고쳐 다시 렌더하면 그 씬의 확인을 처음부터 다시 해야
한다. 그래서 **고칠 것을 모아서 한 번에 고친다.**

```
✗  layout → 1건 고침 → 재렌더 → still → 1건 고침 → 재렌더 → …
✓  layout → 전부 고침 → still → 전부 고침 → 재렌더 → 확인
```

`layout` 은 렌더 없이 돌므로 여러 번 돌려도 싸다. 이미지를 보기
전에 `layout` 이 깨끗해질 때까지 반복한다.

---

## 권장 순서

```
① 콘티 확정 (배치표·색·길이까지)        ← 여기서 최대한 잡는다
② 씬 코딩
③ mv.py layout      (텍스트, 반복 무료)  ← 깨끗해질 때까지
④ mv.py still       (이미지 1장/씬)
⑤ mv.py preview     (타이밍, 필요할 때만)
⑥ mv.py final
⑦ qc.py stats       (텍스트)
⑧ qc.py sheet       (이미지 1장/영상)
⑨ guides / strip    (이상한 곳만)
```

③에서 잡을 수 있는 걸 ⑧에서 잡으면, 그 사이의 렌더와 확인이
전부 낭비다.

---

## 실측

예제 `circle-area` 기준. ③ `layout` 은 4개 씬 전체를 돌리고도
텍스트 몇 줄이고, 실제로 ④~⑧이 못 잡은 title-safe 이탈 1건을
잡았다. 반대로 ③이 못 잡고 ⑧이 잡은 것도 있다 — 자막 전환 시
글자 겹침(전환 **중간** 프레임이라 `play` 종료 시점 검사로는 안
보인다), 자막이 4초 넘게 멈춰 있는 죽은 시간.

**둘 다 필요하다. 순서만 지키면 된다.**
