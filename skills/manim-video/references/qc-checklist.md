# 검수 체크리스트

렌더된 **영상**을 대상으로 한다. 스틸 검사(코딩 중 구도 확인)와는
다른 단계다. 스틸은 "이 순간이 괜찮은가"를 보고, 검수는 "흐름이
괜찮은가"를 본다.

도구: `scripts/qc.py`

```bash
QC=<스킬 디렉터리>/scripts/qc.py

python3 $QC stats  out.mp4              # 자동 검사
python3 $QC sheet  out.mp4 -g 4x4       # 전체 대조표 → Read 로 연다
python3 $QC guides out.mp4 50.0         # 안전영역 가이드 → 자막 위치 판정
python3 $QC strip  out.mp4 36 41 -n 8   # 특정 구간 촘촘히 → 동작 검사
python3 $QC frame  out.mp4 28.3         # 한 프레임 원본 해상도
```

---

## 1단계 — 자동 (`qc.py stats`)

사람이 안 봐도 되는 것부터 걸러낸다.

| 항목 | 판정 |
|---|---|
| 검은 화면 | 씬 첫머리 1초 미만은 정상(Create가 0에서 시작). 그 외 구간은 객체가 화면 밖이거나 `add`를 빠뜨린 것 |
| 4초 이상 정지 | 내레이션이 깔릴 구간이면 정상. 아니면 죽은 시간 |
| 씬 길이 | 60초 초과면 쪼갠다 |
| 해상도/fps | 최종본이 1920×1080@60 또는 3840×2160@60 인지 |

> **freezedetect 의 한계**: 화면에서 아주 작은 부분만 바뀌면
> (예: 물음표 하나가 페이드인) 잡음 임계값 아래라 "정지"로 잡힌다.
> 반대로 자막 한 줄만 바뀌어도 정지가 끊긴다. 숫자를 그대로 믿지 말고
> 그 시각을 `strip`으로 확대해 실제로 뭐가 움직이는지 본다.
>
> **임계값 주의**: `blackdetect`의 흔한 기본값(`pic_th=0.98`)은 이
> 스타일에서 못 쓴다. 어두운 배경에 선과 수식만 있는 화면은 원래
> 픽셀의 98%가 검정이라 멀쩡한 씬이 통째로 잡힌다. `qc.py`는
> `pic_th=0.995, pix_th=0.07`로 잡아둔다. 배경색을 바꿨으면 이
> 값도 같이 봐야 한다.

## 2단계 — 전체 흐름 (`qc.py sheet`)

대조표 한 장을 **Read 툴로 열어서** 본다. 16칸이면 4~5초 간격이라
영상의 뼈대가 한눈에 들어온다.

```
□ 자막과 화면이 어긋난 칸이 없다
   — "고리로 자릅니다"인데 아직 고리가 없는 식
□ 같은 자막이 연속 두 칸에 걸쳐 있지 않다
   — 걸쳐 있으면 그 자막이 4초 이상 정지해 있다는 뜻
□ 빈 칸(아무것도 없는 프레임)이 없다
□ 화면 구성이 씬 사이에 크게 튀지 않는다
   — 수식이 위에 있다가 갑자기 아래로 가면 시청자가 매번 다시 찾는다
□ 색이 일관된다 — 같은 변수가 씬마다 다른 색이면 안 된다
□ 마지막 칸이 결론을 담고 있다
```

자막이 두 칸에 걸친 구간은 **`strip`으로 확대**해서 실제로 그
동안 무엇이 움직이는지 확인한다. 아무것도 안 움직이면 잘라낸다.

---

## 3단계 — 자막·안전영역 (`qc.py guides`)

자막이 있는 시각을 2~3개 골라 가이드를 덧그려 본다.

```
□ 자막이 청록 밴드(하단 20%) 안에 있다
□ 자막이 노란 title-safe(90%) 박스 안에 있다
   — 경계에 "걸친" 것도 실패다. 유튜브 UI/자막 오버레이가 덮는다
□ 자막이 그림과 겹치지 않는다
□ 자막 한 줄이 25자를 넘지 않는다
□ 좌우 중심선 기준으로 구도가 한쪽으로 심하게 쏠리지 않는다
□ 수식/라벨이 title-safe 밖으로 나가지 않는다
```

---

## 4단계 — 동작 (`qc.py strip`)

애니메이션이 실제로 의도대로 도는지 본다. 변형(Transform),
카메라 이동, 궤적 그리기 구간을 8~12칸으로 뽑는다.

```
□ 변형 중간 상태가 알아볼 수 있다 (뭉개져서 정체불명이 되지 않는다)
□ 궤적이 등속으로 흐른다 (끝에서 느려지면 rate_func가 smooth인 것)
□ 겹쳐서 사라지는 요소가 없다
□ 업데이터가 애니메이션 뒤에도 계속 돌지 않는다
   — 다음 play에서 엉뚱하게 움직이면 clear_updaters()를 빠뜨린 것
```

---

## 5단계 — 내용

도구가 못 잡는 것. 스토리보드를 옆에 놓고 대조한다.

```
□ 비트시트의 순서와 영상의 순서가 같다
□ 각 비트의 실제 길이가 기획의 ±25% 안이다
   — 벗어나면 내레이션이 안 맞는다. 어느 쪽을 고칠지 정한다
□ 그림이 기호보다 먼저 나온다
□ 자막과 화면 속 라벨이 같은 말을 중복하지 않는다
   — 화면에 "고리의 길이 = 2πt"가 있는데 자막도 "이 고리의 길이는
     2πt입니다"면 하나는 지운다
□ 설명 없이 지나가는 기호가 없다
□ 결론이 화면에 남는다
```

## 보고 형식

검수가 끝나면 발견한 것을 이렇게 정리한다. **"확인했습니다"만
쓰지 않는다** — 무엇을 어떻게 봤는지가 있어야 한다.

```markdown
## 검수 결과 — <파일명> (<길이>s)

### 자동
- 검은 화면: 없음
- 4초 이상 정지: 3건 (7.9s/5.3s, 51.3s/5.5s, 57.7s/4.4s)

### 눈으로 (sheet 4x4, guides 3장, strip 1구간)
| 시각 | 문제 | 판정 | 조치 |
|---|---|---|---|
| 15~20s | 자막이 두 칸에 걸침, 그동안 고리만 천천히 참 | 죽은 시간 | LaggedStart run_time 3.2→2.4 |
| 50.0s | 자막이 title-safe 하단선에 걸침 | 잘릴 위험 | subtitle buff 0.45→0.55 |

### 고치지 않은 것
- 57.7s 정지 4.4초 — 결론 수식을 읽는 시간. 내레이션이 들어갈 자리라 유지.
```

고치지 않기로 한 것도 **왜 그런지와 함께** 적는다. 빠뜨린 것과
의도적으로 남긴 것을 구분할 수 있어야 한다.
